RESULT LANGUAGE

Understanding LANVEXA results

A useful network result must distinguish a failed test from a test that did not run and from information that was never advertised.

PASS
The configured check completed and met its defined success condition.
FAIL
The configured check ran and did not meet its success condition.
NOT TESTED
The check was not run or could not appropriately proceed. Its outcome remains unresolved.
NOT DETECTED
Expected passive evidence, such as an LLDP/CDP advertisement, was not observed during the observation window. This is not a connectivity failure.

After one first-pass test

The result is designed to show the selected wired interface, addressing state, configured gateway, DNS and TCP outcomes, and any LLDP/CDP neighbor identity or advertised Port ID that was observed. It should also make clear which checks were not completed and which passive information was not observed.

What remains unknown

These observations do not establish cable wiremap, cable length, distance to fault, PoE load capability, physical-layer quality, or switch configuration state. An absent LLDP/CDP advertisement does not establish network failure.

Bounded summaries

“Configured connectivity checks passed” means only that the checks shown in that result passed. It does not certify the cable, validate every application path, or establish that the network is broadly healthy.

Example combinations

Gateway passes; DNS fails

The local gateway responded, but the configured name-resolution check did not. LANVEXA shows both observations without claiming the root cause.

Connectivity passes; no neighbor detected

The L3/L4 checks succeeded, but no LLDP/CDP advertisement was observed. The network can remain usable even though switch and port information are unavailable.
