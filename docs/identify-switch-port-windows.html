WINDOWS / SWITCH DISCOVERY

How to identify the connected switch or port from a Windows laptop

A laptop can provide useful clues about the neighboring switch, but no single method guarantees a physical-port mapping in every environment. Treat an advertised Port ID as evidence to corroborate, not certainty.

Common approaches

Switch-side MAC-table lookup

A network administrator can look for the laptop adapter's MAC address in the switching environment. This can be authoritative within the observed topology, but it requires management access and careful handling of uplinks, learned addresses, and recent moves.

LLDP/CDP observation

A directly connected switch may advertise its identity and Port ID. This requires the protocol to be enabled, an advertisement to arrive, and the Windows capture environment to expose it.

Packet analysis

A packet analyzer can inspect discovery frames directly. This is flexible and detailed, but the operator must select the correct interface, capture safely, and interpret the protocol fields.

Dedicated network tester

Depending on the device, a dedicated tester may combine neighbor discovery with physical-layer functions such as wiremap, TDR, qualification, or PoE loading.

LANVEXA's intended workflow

LANVEXA is designed to combine passive LLDP/CDP observation with a repeatable set of basic connectivity checks on the Windows laptop already onsite. It aims to make the narrow first pass easier to read; it does not replace switch management or physical-layer testing.

A practical first pass

  1. Connect the intended wired adapter to the wall jack.
  2. Confirm the selected adapter and link state.
  3. Review addressing and configured connectivity checks.
  4. Allow time for an LLDP/CDP advertisement.
  5. Record the protocol, neighboring identity, and advertised Port ID when present.
  6. Corroborate the observation through switch-side data or deeper tools when the ticket requires certainty.

When nothing is advertised

Continue using the connectivity results. No advertisement may reflect device configuration, timing, adapter behavior, or the selected interface; it is not proof of network failure. See No neighbor detected.
